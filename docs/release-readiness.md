## 1. 当前版本基线

`0.3.6` 在可持续续编的数据库设计评审工作台基础上完成了大图交互性能治理，当前闭环为：

```text
SQL DDL → 解析与关系推断 → 布局/连线精调 → 评审决策与批注
        → 评审报告 / 标准数据库说明书 / 工作区存档
```

已纳入发布口径的能力：

- 多工作区存档合并：保留来源组的相对布局、路由、模块边界与评审状态；冲突时拒绝原子导入。
- 加密工作区存档：新存档可用密码保护，旧版未加密存档仍可导入。
- 布局精调：Alt 水平移动、Shift 纵向微调、多选对齐/分布/等宽，以及新增表时保留已有布局。
- 字段顺序：编辑模式下通过三杠握柄拖动，排序与连线端点使用一致的呼吸提示；顺序随存档和增量 SQL 保留。
- 画布快控：右键直接缩放、全览和切换网格；底部缩放统一为 15%～100% 六档。
- 增量续编：追加 SQL 时保留布局、路由与评审状态；分片表合并改名时按物理身份重映射。
- 评审记录：表级“标记删除”和字段级结构化意见可导出为表格。
- 标准文档：导出包含文档控制、数据字典、主键/索引、关系和术语等章节的数据库设计说明书。
- 发布产物：标准 SPA、单文件 HTML、Landing Page 和 GitHub Release 自动化流程均已配置。
- 性能交互：画布与卡片拖动采用增量几何同步、局部预览布线和落点精修；移动期间可在底部中央查看实时 FPS。
- 性能证据：仓库内置可复现 benchmark、预算检查与 Playwright 回归，PR 跑 smoke、定时任务跑完整拓扑矩阵。

## 2. 发版证据清单

每次候选版本至少保留以下证据：

| 类别     | 必要检查                            | 通过标准                                  |
| -------- | ----------------------------------- | ----------------------------------------- |
| 代码     | `bun run typecheck`                 | 无 TypeScript 错误                        |
| 代码     | `bun run lint`                      | 无新增错误；既有 warning 需记录           |
| 测试     | `bun run test`                      | 全部通过                                  |
| 构建     | `bun run build`                     | SPA 构建成功                              |
| 离线产物 | `bun run build:single`              | 生成 `dist-single/er-diagram-viewer.html` |
| 浏览器   | `bun run test:e2e`                  | 导入、布局、拖拽与 FPS 反馈主链路可用     |
| 性能     | `bun run perf:smoke` + `perf:check` | 交互动作有效且未突破帧预算                |
| 存档     | 未加密/加密/错误密码/多文件合并     | 兼容旧档；错误输入不覆盖当前工作区        |
| 文档     | README、CHANGELOG、Landing、版本号  | 功能描述与当前实现一致                    |

## 3. 推荐冒烟场景

1. 导入内置样例，确认搜索范围、阅读/编辑模式和模块批量调整。
2. 拖动一个字段排序，再追加 SQL 字段；确认旧顺序和表卡位置不被重排。
3. 标记一张表删除，添加一条字段意见，导出评审报告并检查表格列：时间、表、字段、建议。
4. 导出标准数据库说明书，确认只包含当前可见表和已确认关系。
5. 导出未加密和加密工作区存档，分别导入；再选择两个存档合并，确认冲突会原子拒绝。
6. 平移画布、横向/纵向滚动和拖动表格，确认底部中央 FPS 随移动实时变化，停止后自动收起。
7. 执行 `build:single` 后以 `file://` 打开，重复第 2～6 步的最小链路。

## 4. 当前风险与下一阶段候选

### 发布前应持续关注

- 解析器仍不支持 `ALTER TABLE ... ADD COLUMN` 和 PostgreSQL `COMMENT ON`；会产生告警或丢失结构/注释。
- 跨 schema 的同名表仍可能发生裸表名串扰。
- 大型 schema 的解析、推断和初次布局仍在主线程执行；现有矩阵尚未达到启用 Worker / LOD 的阈值。
- hub 高出度场景仍是最重交互拓扑，应通过定时完整矩阵持续观察。

### 下一中期版本候选

按风险和收益排序，建议优先考虑：

1. 修复 `ADD COLUMN`、`COMMENT ON` 和跨 schema 标识问题，并补充回归样例。
2. 增加 schema lint，将无主键、缺索引、缺注释等问题转为可确认的评审项。
3. 增加 schema diff，支持“变更前/变更后”并排评审和差异报告。
4. 将报告/说明书导出模板化，并补充 Mermaid / DBML 输出。
5. 将一条 Playwright 冒烟和单文件 `file://` 检查纳入发布工作流。

- `CLAUDE.md`：维护架构、不变量、开发约定和已知坑。
- `docs/SQL_PARSER.md`：维护解析器专项边界与实现依据。
- `docs/palette-professional.md`：维护沉稳配色的设计约束和验证数据。
- 本文：维护中期发布证据和下一阶段准入条件；不记录逐轮开发流水账。
