# 自定义模块与模块配色

实施与回归日期：2026-09-12。基于当前 0.3.6 工作分支，保留之前的字体清晰度和配色调整。

## 如何使用

1. 进入编辑模式，用 Shift / ⌘ 多选表。在底部模块下拉框选择「＋ 新建自定义模块…」，输入名称，点击「创建并移入」。原有「移到其他模块」和「恢复自动分组」继续可用。
2. 名称会去掉首尾空白，最多 64 个字符；不允许空名称、换行和控制字符。同名模块直接复用；若合并的存档中存在多个同名模块，则提示用户重新选择目标或换一个名称，不擅自决定。
3. 左侧模块列表中，点击名称仍然是定位；点击前面的色块则打开颜色编辑器。可以点预设色、使用系统取色器，或者输入六位 HEX。
   预设色上方标注「色板来源：沉稳 · 当前画布配色」，名称和 12 个色块一起跟随右上角的配色组。该说明只表示预设色盘来源；取色器和 HEX 独立标注为「自定义颜色」，不声称自定义色来自当前色板。此处没有新增配色组切换入口。
4. 颜色先在编辑器中预览，点击「应用」才更新画布；「取消」或 Escape 丢弃草稿。「恢复默认颜色」撤销该模块的手选颜色。
5. 顶部切换整套配色时保留手选色。为延续已有的统一标题字色策略，过浅或过深的颜色可能被调整到可读的表头色；编辑器会明确显示实际表头色。对应色系的标题字色不因单个模块改色而翻转，亮/暗背景连线各自使用可读性派生色。

## 数据与兼容性

- 不修改 DDL。自定义分组仍叠加在自动推断结果上。
- 新增 `customModules`（稳定内部标识、显示名称、色系、固定色位）和 `moduleColors`（用户原始 HEX）。沿用 `moduleOverrides` 保存每张表的归属。内部标识不显示在表头或 SVG 中。
- 会话恢复、增量 SQL 更新、重新推断、工作区存档导入/导出均保留新字段。新导入一份独立 SQL 时清空这些设置，与原有工作区替换行为一致。
- 仍使用 archive version 1 / persist version 2，字段是可选扩展。旧存档缺省为空，不会继承当前画布的手选色；旧版程序无法显示新功能，重新导出时也无法保留新字段。
- 布局、视口、表宽、列顺序、路由、评审信息保持原有存储方式。应用程序只读取用户导入的存档；本次开发没有覆盖用户已有存档文件。
- 普通多存档合并时，为模块定义、颜色和表归属添加同一来源前缀，避免同名/同标识混淆。
- 边界保护：已经合并过的存档再次合并时，原有流程可能折叠其模块推断范围。如果无法保留已生效的人工分组或配色，合并预检会报错并取消，不静默丢弃；该存档仍可单独打开。此处没有扩展为新的多层工作区合并算法。
- 模块恢复使用「恢复自动分组」和「恢复默认颜色」。没有改变现有仅针对画布布局的撤销/重做范围。

## 实现与性能边界

Graphify 的依赖查询帮助定位了分组推断、会话持久化、存档合并和导出的共同路径；实现放在统一的 `pipeline` 中，让侧栏、表头、连线及 SVG/PNG 使用同一份结果。

颜色草稿保存在编辑器的局部 React 状态里，拖动系统取色器不会持续重算整张图。编辑器仅在打开时挂载；点击应用只重算模块，不重新解析 SQL，也没有新增常驻动画或逐帧任务。

### 小规模性能烟测

对比此前 `perf-results/palette-expansion-smoke/baseline.json` 与本次 `perf-results/custom-modules-smoke/baseline.json`。同为 Chromium 151、1440×1000、DPR 1、14 表、3 轮、无预热、24 移动步、步间隔 8 ms；以下为每轮指标的中位数。

| 指标 | 上次配色更新 | 本次模块更新 |
| --- | ---: | ---: |
| 导入耗时 | 150.0 ms | 146.4 ms |
| 画布平移 FPS | 120.0 | 120.0 |
| 画布平移 P95 帧耗时 | 8.9 ms | 9.2 ms |
| 表拖动 FPS | 120.1 | 120.0 |
| 表拖动 P95 帧耗时 | 8.5 ms | 8.7 ms |
| 阅读 / 编辑 DOM 数 | 1189 / 1390 | 1216 / 1417 |
| 空闲动画 | 0 | 0 |

新增入口增加了 27 个 DOM 节点；本次三轮未记录交互长任务，帧率仍接近测试环境的 120 Hz。P95 帧耗时有 0.2–0.3 ms 上升，不据此宣称性能提升或完全没有开销。这只是小规模烟测，不替代大模型、真实投屏设备和长时间操作评估。
