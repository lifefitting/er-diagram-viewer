# 画布 FPS 触发覆盖修复

日期：2026-09-12。

## 原因与修复

原实现只在鼠标拖拽或滚轮输入时启动 HUD。搜索回车、模块定位和缩放控件通过程序改变视口，虽然经过同一套画布更新逻辑，但没有启动 FPS 采样，因此不显示。

结合 Graphify 定位的视口与导航依赖，现改为在 DiagramCanvas 统一监听 `pan / zoom`，比较真实相机值，覆盖搜索 Enter / Shift+Enter、模块定位、点击聚焦、缩放按钮、全览、100% 恢复、选中区域缩放、工作区定位以及鼠标平移/捏合缩放。不在每个按钮里分别维护启动和停止逻辑。

## 显示与性能规则

- FPS 仍来自已有画布几何刷新回调的时间间隔，没有新增持续运行的 rAF 或轮询。HUD 状态更新只影响自身，不重渲染表内容。
- 同一连续交互重复启动不会清空已采集的样本；同一帧内重复的几何/节点刷新只计一次，避免零时间间隔干扰读数。
- 相机停止变化 180 ms 后隐藏；达到缩放边界等未实际改变画布的操作不启动 HUD。搜索输入只改变高亮、不移动视口时也不启动。
- 单次瞬间缩放可能只有一帧，因此显示 `-- / SAMPLING CANVAS UPDATES`；有连续真实更新后才计算 FPS，不用空闲刷新率补造数值。
- 表拖拽保持原有行为：拖动时显示，按住不动时变为 0，松开后隐藏。视口计时器不会关闭正在进行的表拖拽 HUD；组件卸载时清理计时器。
- 不改变视口移动方式、动画时长或存档字段；不修改用户已有存档文件。

## 验证

415 项单元测试、29 项浏览器测试通过。新增单测覆盖真实变化判定、连续动作、表拖拽优先和卸载清理；新增浏览器回归覆盖搜索前后跳转、无结果、模块定位动画、缩放按钮/菜单、缩放上限、捏合缩放及手动平移。原有字段拖拽、表拖拽暂停恢复、水平/垂直滚轮及无表内容重渲染测试通过。

TypeScript 与正常/单 HTML 构建通过；ESLint 0 error，保留 7 项已有 warning。实际在 `file://` 单 HTML 中验证搜索、模块定位和缩放 HUD，停止后隐藏，浏览器错误及 HTTP 请求均为 0。

| 编辑模式 DOM | 1417 | 1417 |

本次小样本未见明显交互退化，不能据此推断所有设备、大模型下的表现，也不把小幅波动当作确定的性能提升。原始记录位于 `perf-results/viewport-fps-smoke/baseline.json`。
