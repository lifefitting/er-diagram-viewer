# 「专业」配色（professional palette）设计记录

> 2026-07-12 引入，`src/infer/inferModules.ts` 中 `MODULE_PALETTES.professional`。
> 本文记录设计约束、验证方法与最终数值，便于日后调整时按同一标准复核。
> 原则：**颜色是可计算的，就用计算验证——不靠肉眼**。

## 设计约束

模块色在本工具中同时承担四个角色：表卡头部背景（白字）、连线颜色（亮画布）、
连线颜色（暗画布，`headerDark`）、模块面板色块。约束按此推导：

| 约束 | 数值 | 原因 |
| --- | --- | --- |
| 头部明度（OKLCH L） | 0.43–0.58 | 白字 WCAG AA（≥4.5:1，13px 表名是普通字号） |
| 彩度下限（OKLCH C） | ≥ 0.10 | 低于此值读作灰色，失去模块辨识作用 |
| 亮画布对比 | ≥ 3:1 vs `#ffffff` | 连线可见性（WCAG 非文本标准） |
| 暗画布对比 | ≥ 3:1 vs `#0b1020` | 同上，作用于 `headerDark` |
| 暗色变体明度 | OKLCH L 0.48–0.67 | 暗色模式明度带，避免刺眼或不可见 |
| 相邻槽位 CVD 分离 | Machado ΔE ≥ 12（实测 ≥ 36） | 模块按大小取槽，最大的几个模块拿到色觉障碍下最可分的颜色 |

## 方法

1. 在 OKLCH 空间取 12 个色相（denim/olive/plum/terracotta/steel/sea/violet/
   pine/indigo/burgundy/bronze/rose），L 0.44–0.55、C 0.10–0.12——「低饱和、
   沉稳」由彩度上限约束，「不发灰」由彩度下限约束；
2. 槽位顺序用爬山法优化：固定槽 1 = denim（专业工具主导色应为蓝），
   最大化最小相邻 CVD ΔE（Machado 2009 protan/deutan 模拟）；
3. **暗色变体不用自动 HSL 提亮**（`darkEdgeColor` 保饱和度提亮会把深青
   `#00736e` 炸成霓虹 `#29fff6`），而是同色相在暗色明度带内重新取阶，
   蓝紫家族（denim/indigo/steel/violet）额外按明度分层——紫色在红绿色盲下
   丢失红分量后与蓝色坍缩，只能靠明度区分；
4. 每次调整跑 dataviz 技能的 `validate_palette.js` 双模式验证。

## 已知极限（有意接受）

**全对两两（all-pairs）CVD 分离做不到。** 12 个色相中必然存在红绿对
（burgundy↔pine 等）在红绿色盲模拟下坍缩（ΔE < 2）——这是色域数学极限，
所有 12 槽配色（包括既有四套）皆然。缓解：模块身份从不单靠颜色——表卡上
有表名、连线物理连接到源卡片、模块面板有文字标签（dataviz 规则中的
「二级编码」）。正常视觉 all-pairs 最小 ΔE 亮 13.2 / 暗 12.5。

sea 槽（`#008660`）是手工微调值：青绿色相在 sRGB 色域中「C ≥ 0.10 且白字
≥ 4.5」的交集极窄，199 系深青全部不可行，最终在色相 165° 附近穷举 hex 取得。

## 架构接点

- `ModuleColor.headerDark?`：可选字段；`buildGraph` 中
  `colorDark: moduleColor.headerDark ?? darkEdgeColor(color)`——
  未提供暗变体的旧配色仍走自动提亮，行为不变。
- 新配色为 `DEFAULT_PALETTE`（新会话生效；已有会话的 palette 已持久化不受影响）。
- 工具栏切换入口是调色盘图标按钮（下拉里保留各配色的色条预览）。
