# 配色扩展与可读性报告

日期：2026-09-11。对比基线：`1901426`（0.3.6）。本次不修改版本号。

## 用户可见变化

右上角色系从 5 套增加到 8 套，默认仍为「沉稳」，保留「明快、柔和、大地、单色」。新增：

| 色系 | ID | 设计取向 |
| --- | --- | --- |
| 青瓷 | `qingci` | 青绿、珊瑚与紫色搭配，适合日常查看 |
| 暮光 | `twilight` | 紫红、橄榄与琥珀交错，亮暗模式均可用 |
| 高辨识 | `contrast` | 更明显的明暗层次，用于演示时区分模块 |

「高辨识」前六个表头的基础色参考 [Paul Tol Bright](https://sronpersonalpages.nl/~pault/)；为统一白字，部分最终背景已调深。后六色与连线明暗变体是本项目的扩展，不等同于原方案完整的色觉安全承诺。

下拉菜单显示六色色条预览，向左展开、右边缘对齐触发按钮，限制最大高度并支持内部滚动，避免增加选项后溢出屏幕。

## 修复了什么

- **表头与连线不再共用一个亮色值。** `header` 保留模块表头色；新增可选 `edgeLight`，历史字段 `headerDark` 继续表示暗画布连线色。柔和配色仍是浅色表头，但连线不会随之淡到难以辨认。
- **同一配色统一文字色。** 柔和统一使用 `#1f2937`，其余七套统一白字。背景对比度不足 4.5:1 时调整背景明暗，不再逐表选择黑字或白字；亮暗模式使用相同规则。
- **小标签也保留对比度。** 去掉表头模块名的额外文字透明度；分表数量徽标改为透明背景与文字同色边框，避免叠加白底后降低白字对比。SVG/PNG 同步这一表现。
- **连线计算包含透明度。** 普通连线最低不透明度为同模块关系的 0.6。按此与画布背景合成后，向黑/白做中性混合，目标对比度为 3.05:1，留出量化余量。低置信度、待确认逻辑关系及主动弱化状态保留原有透明度语义。
- **第 13 个模块以后继续分配颜色。** 保留前 12 槽位顺序，再按确定性层级生成同色系变体并缓存。扩展色继承该色系的统一字色，背景向远离文字明度的方向变化，避免产生同一对比度边界上的重复颜色。不再全部使用同一灰色，也没有运行时随机颜色。

文字 4.5:1 和图形 3:1 是参考 [WCAG 普通文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)与[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)确定的工程目标，不代表整个应用已经通过 WCAG 认证。

## 与旧配色的量化对比

均取原有 12 个基础槽位中的最小值。亮画布 `#f6f8fb`，暗画布 `#0b1020`；连线按 0.6 不透明度合成计算，不能与旧设计记录中直接比较不透明 HEX 色值的结果混用。

| 色系 | 表头文字对比度：前 → 后 | 亮画布连线：前 → 后 | 暗画布连线：前 → 后 |
| --- | --- | --- | --- |
| 沉稳 | 4.59 → 4.59 | 2.31 → 3.05 | 1.93 → 3.05 |
| 明快 | 3.09 → 4.56 | 1.81 → 3.05 | 1.93 → 3.05 |
| 柔和 | 5.74 → 8.14 | 1.06 → 3.05 | 4.46 → 4.46 |
| 大地 | 5.25 → 5.47 | 2.49 → 3.05 | 2.19 → 3.05 |
| 单色 | 4.55 → 4.58 | 1.22 → 3.05 | 2.21 → 3.05 |

对照直接读取 Git 基线的配色定义。修复字色不统一后，明快、单色以及高辨识中部分浅色表头会调深以支持统一白字；原有槽位顺序、模块身份和几何信息不变。沉稳、柔和、大地的基础表头背景保持原值。

八套色系各测试到 160 个模块：所有表头文字对比度均 ≥4.5:1；所有普通连线在亮/暗背景合成后的对比度均 ≥3:1，实际最低约 3.05:1。亮色 SVG 的白色背景也覆盖在单测中。

160 槽中，柔和、大地各有 159 个不同的表头 HEX 值，其余六套各有 160 个。扩展颜色解决的是统一灰色回退，不保证任意规模、任意两模块的颜色都独一无二或肉眼可分。

## 色觉差异检查与边界

`bun perf/palette-audit.ts` 可离线复核。使用 Machado 2009 的 protan/deutan/tritan 三种 severity=100 矩阵，在线性 sRGB 上模拟、裁剪到显示色域，再转换到 CIELAB D65，计算 ΔE76。矩阵核对来源为 [Colorspacious 实现及其论文出处](https://raw.githubusercontent.com/njsmith/colorspacious/master/colorspacious/cvd.py)。这不是 CIEDE2000，也不是通用的色觉无障碍通过/失败标准。

新增色系的槽位顺序在开发阶段做了离线优化，综合表头、亮色连线与暗色连线的相邻区分度；高辨识保留前六槽，仅调整扩展槽。最终顺序直接写入常量，不在用户机器上求解。随后统一字色的修复保留这一顺序，但高辨识的部分背景调深，下面重新计算其区分度，不沿用修复前的较高数值。

| 新色系 | 表头相邻最小 ΔE76 | 暗连线相邻最小 ΔE76 | 表头任意两色最小 ΔE76 |
| --- | --- | --- | --- |
| 青瓷 | 26.07 | 17.87 | 3.11 |
| 暮光 | 32.41 | 14.92 | 1.79 |
| 高辨识 | 3.11 | 8.45 | 2.00 |

取三种模拟中的最差结果；暗连线先与背景按 0.6 不透明度合成。表头在亮暗主题中使用同一颜色。最后一列仍然偏低，因此不能仅靠颜色识别所有模块：继续保留模块名称、表名与连线端点等非颜色信息。

本次没有增加投影仪自动检测或新的显示模式。投屏环境的环境光、屏幕白点、显示器设置和细线抗锯齿都可能进一步影响视觉对比；现有亮/暗/跟随系统模式保持不变，需要在实际受影响的设备上复核。原「沉稳」设计文档保留为历史记录，但旧 CVD 结果不能直接用于当前的新口径。

## 性能与兼容性

配色目录成为工具栏和存档校验的共同来源，避免新增 ID 在会话恢复或合并工作区时被当作非法值丢弃。这一接入范围先通过 Graphify 的配色依赖查询定位，再核对源码确认。

基础色的对比度修正在模块初始化时完成，扩展色首次分配后按色系和槽位缓存。拖动与滚轮动画只读取已计算的颜色，没有新增逐帧计算、动画或事件监听。未添加运行时依赖。

工作区格式仍为 `formatVersion=1`、`persistVersion=2`。颜色派生值不写入存档；只保存原有 `palette` ID。旧版 v0.3.x 文件、加密存档与合并分组均保留原有处理路径，布局、连线控制点、字段顺序和批注不做迁移，也未读写用户已有的存档文件。导入仍保留用户当前亮暗主题偏好，不用存档中的主题覆盖它。

兼容范围是**新版读取旧存档**。旧程序不认识三个新色系 ID，打开新色系存档时可能回退到默认配色，不能保证旧程序识别新配色。

## 验证结果

- 字色一致性修复后重新通过 403 项单测和 22 项浏览器回归。新增每套色系 160 槽字色一致性及背景修正检查；SVG/PNG 共用渲染器、亮暗页面均断言所有表头使用该色系的统一字色，普通/单 HTML 构建均重新通过。此次颜色修正在初始化及模块分配阶段完成，不增加逐帧计算。
- 初版 393 项单元测试、22 项浏览器回归通过，覆盖八套配色、160 槽对比度、SQL 重排后颜色稳定、存档及合并组的 ID 保留、SVG/PNG 共用渲染器、亮暗切换和刷新恢复。
- 原有列拖动、连线、对齐菜单、横纵滚轮 FPS，以及 DPR=1/1.25/2 与跨屏字体定位场景全部回归通过。
- 类型检查、普通生产构建、单 HTML 构建通过；lint 为 0 错误、7 个原有警告。
- 字色修复后直接通过 `file://` 打开单 HTML，加载 14 张表示例、切换暗色和高辨识配色、导出 SVG（41,880 字节）及 PNG（944,968 字节）并刷新恢复成功；HTTP 请求与页面错误均为 0。首次临时脚本误用 button 角色查找 menuitem，修正测试选择器后通过，产品代码无需调整。
- 生产构建小图性能冒烟：3 次正式样本、24 步手势、8 ms 步间隔、DPR=1；平移约 120.0 FPS，拖表约 120.1 FPS；每轮 P95 的中位数分别为 8.9 ms、8.5 ms。空闲动画为 0，绝对性能门禁通过。

性能原始报告：`perf-results/palette-expansion-smoke/baseline.json`。这是单目标冒烟，不是新增配色的全规模前后 A/B，不能据此声称性能进一步提升。此前字体修复的 DPR=1/2 完整前后对比见 [非 Retina 字体清晰度报告](non-retina-text-clarity.md)。
